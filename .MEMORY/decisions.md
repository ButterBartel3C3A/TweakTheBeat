# 技术决策日志（ADR 风格）

格式：编号 / 状态（待决|已决|废弃）/ 日期 / 结论 / 理由。只追加不改写。

## 已决

### D0 — 项目记忆存放位置
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：项目记忆统一放仓库 `.MEMORY/`，跨 agent 共享、随仓库推送；会话个人记忆仅留指针与用户偏好。
- 理由：保证跨 agent 可操作/可维护，协作可见。

### D1 — 数据源文档与仓库的关系
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**直接引用**本机外部数据源，不复制进仓库；数据源身份/路径保密——仅存本机会话个人记忆，仓库文本一律不记录其名称与路径（约定见 `.MEMORY/README.md` 保密约定）。
- 理由：用户拍板「仅直接引用」；外部数据源为商用闭源，不得在云端文本中描述其存在。

### 脱敏策略 — 设备/品牌代号
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：仓库保持公开；公开文本一律以「目标设备」代号指代被测设备，不出现品牌/产品名/广播名/协议 UUID/帧值（细则见 `.MEMORY/README.md` 保密约定）；细节以本机需求文档（未跟踪）与个人记忆为准。
- 理由：降低项目意图可识别度。

### D6 — 代码布局与提交边界
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：公开仓库提交**协议无关框架（ble-cli core）+ 通用文档 + 示例 profile（占位符 UUID）**；目标设备真实 profile 配置、用例执行配置、SKILL（含真实标识）**留在本地不提交**（gitignore 由用户管理）。具体目录结构随第八节第 2 问起草时给出。
- 理由：符合「框架可独立开源」目标 + 公开仓库脱敏要求。

### D5 — 技术栈选型
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**argparse + TOML**；TOML 用 Python 3.11+ 内置 tomllib 解析；唯一第三方运行时依赖 = bleak（最新稳定版锁定）。Python ≥ 3.11。
- 理由：零额外依赖、`--json` 输出纯净可控（typer 的 help/错误输出是干扰源；YAML 有隐式类型转换坑）。

### D2 — profile 配置驱动与代码钩子分界线
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**配置为主 + 钩子保底**。常规帧编解码/握手序列/位域/上行分类用 TOML 声明式表达；复杂逻辑（float 解码、条件位域、特殊校验）允许 profile 目录内一个 adapter.py 提供固定接口的纯函数钩子（bytes→结构化 dict），不碰 core。
- 理由：纯配置覆盖绝大多数场景，钩子作为保底逃生舱；避免 100% 纯配置的 DSL 复杂度失控，也避免每 profile 全写代码。
