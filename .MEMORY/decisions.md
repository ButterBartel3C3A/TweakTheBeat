# 技术决策日志（ADR 风格）

格式：编号 / 状态（待决|已决|废弃）/ 日期 / 结论 / 理由。只追加不改写。

## 已决

### D0 — 项目记忆存放位置
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：项目记忆统一放仓库 `.MEMORY/`，跨 agent 共享、随仓库推送；会话个人记忆仅留指针与用户偏好。
- 理由：保证跨 agent 可操作/可维护，协作可见。

### D1 — 数据源文档与仓库的关系
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**直接引用**本机外部数据源，不复制进仓库；数据源身份/路径保密——仅存本机会话个人记忆，仓库文本一律不记录其名称与路径（约定见 `.MEMORY/README.md` 保密约定）。
- 理由：用户拍板「仅直接引用」；外部数据源为商用闭源，不得在云端文本中描述其存在。

### 脱敏策略 — 设备/品牌代号
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：仓库保持公开；公开文本一律以「目标设备」代号指代被测设备，不出现品牌/产品名/广播名/协议 UUID/帧值（细则见 `.MEMORY/README.md` 保密约定）；细节以本机需求文档（未跟踪）与个人记忆为准。
- 理由：降低项目意图可识别度。

### D6 — 代码布局与提交边界
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：公开仓库提交**协议无关框架（ble-cli core）+ 通用文档 + 示例 profile（占位符 UUID）**；目标设备真实 profile 配置、用例执行配置、SKILL（含真实标识）**留在本地不提交**（gitignore 由 AI 维护、用户审阅）。具体目录结构随第八节第 2 问起草时给出。
- 理由：符合「框架可独立开源」目标 + 公开仓库脱敏要求。

### D5 — 技术栈选型
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**argparse + TOML**；TOML 用 Python 3.11+ 内置 tomllib 解析；唯一第三方运行时依赖 = bleak（最新稳定版锁定）。Python ≥ 3.11。
- 理由：零额外依赖、`--json` 输出纯净可控（typer 的 help/错误输出是干扰源；YAML 有隐式类型转换坑）。

### D2 — profile 配置驱动与代码钩子分界线
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**配置为主 + 钩子保底**。常规帧编解码/握手序列/位域/上行分类用 TOML 声明式表达；复杂逻辑（float 解码、条件位域、特殊校验）允许 profile 目录内一个 adapter.py 提供固定接口的纯函数钩子（bytes→结构化 dict），不碰 core。
- 理由：纯配置覆盖绝大多数场景，钩子作为保底逃生舱；避免 100% 纯配置的 DSL 复杂度失控，也避免每 profile 全写代码。

### D3 — 物理刺激用例的无交互交互协议
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**操作指引 + 阻塞等待 + confirm 子命令**。执行器遇物理刺激用例：打印指引（--json 输出含指引）→ 阻塞等待上行 → 测试员操作后跑 `confirm` 子命令（读状态文件恢复）继续；支持 `--timeout N` 自动超时（超时按 FAIL 或 MANUAL 处理，细节随执行器设计定）。AI 跨调用靠状态文件恢复。
- 理由：人操作时间不可控，固定超时窗口易误判；confirm 把控制权交给测试员，同时保持无内存态。

### D4 — 用例文档解析容错
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**校验报告 + 降级 MANUAL**。解析器把用例表转成结构化列表；`cases list --validate` 出校验报告（坏行/缺失字段/hex 失败定位到行号）；执行时解析失败的用例自动标 MANUAL 并附原始行文本。
- 理由：表格人工维护必然漂移；坏行不阻塞全量，且可溯源修复。

### D8 — 退出码粒度
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**三档 + JSON error.code**。退出码只 0 成功/1 执行失败/2 用法错误；细分信息放 `--json` 输出的 `error.code` 字符串字段（如 device_not_found/timeout/write_failed），脚本按字段分支。
- 理由：blescope 约定简洁好记；结构化字段保证可扩展性，无需膨胀码表。

### D9 — SKILL 版本策略
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**仅仓库脱敏版（单一文件）**。SKILL 提交进仓库（`.claude/skills/ble-cli/SKILL.md`，需从 gitignore 豁免——gitignore 由 AI 维护、用户审阅），内容脱敏：代号「目标设备」+ 占位符，不出现真实标识；指引本机会话读工作树 `ble-automation-prompt.md`（未跟踪）获取真实值。**不维护本地完整版**。
- 理由：单份免同步成本；验收标准 4 相应演变为「仅凭 SKILL + 本机需求文档」完成指定用例。

### D10 — 真机冒烟节奏
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：**一次性全量冒烟**。全部实现完成后，一次性跑完人类模式 + AI 模式冒烟与 P0 用例执行（需求原文方案）；物理刺激用例届时用户在设备旁配合。
- 理由：用户拍板；实现阶段不碰真机，集中精力交付。

### D7 — 断言规则格式（需求第八节第 3 问部分）
- 日期：2026-09-22　状态：已决（用户拍板）
- 结论：每用例一个 TOML 规则文件（`.local/cases/asserts/<用例ID>.toml`），渐进覆盖——无规则文件的用例默认「注入+日志+MANUAL」。禁止字符串匹配；规则 = 注入帧序列 + 断言窗口（timeout_ms）+ expect（时序匹配，支持 XX 通配/+4B 长度/计数/递增/钩子检查）+ expect_not + expect_none + 可选 divergence（→ 自动 MANUAL）；自然语言部分转测试员指引/人工检查项。
- 理由：协议知识以数据承载，与框架同构可复用（定稿见 design.md 第 3 节）。

## 待决

### D11 — AI 模式长连接（daemon 子命令，候选）
- 日期：2026-09-23　状态：待决（用户冒烟后提议，未立项）
- 背景：用户希望 long run 终端避免反复重连（澄清：目标设备无配对环节，32s 无连接休眠需旅行锁唤醒；BLE 连接无法跨进程共享，故 AI 模式每命令独立连接）。
- 候选结论：daemon 子命令——后台进程持连接 + 状态文件/命名管道命令通道，AI 逐命令投递、复用同一连接。
- 待用户拍板；另两项衍生待办：C1.1 类"不握手会话"用例支持、.gitignore 审阅。
